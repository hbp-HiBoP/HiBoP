# S0 — Open-visualization operation and dependency matrix

Source audit of `feature/xr-autonomous`, 2026-09-17. This is an inventory and a schema input, not an implemented synchronization contract or a device validation result. An operation is in scope when it changes the scientific scene or visible content of an already open visualization. The proposed fields and atomic groups below must be finalized in S1; no row marked **gap** may be silently deferred from the first Desktop-to-Quest release. Paths in the table are relative to the repository root. `UI/Toolbar` means `Assets/Scripts/HBP/UI/Toolbar`; `UI/Module3D` means `Assets/Scripts/HBP/UI/Module3D`; `UI/Tools` means `Assets/Scripts/HBP/UI/Tools`; `Data/Module3D` means `Assets/Scripts/HBP/Data/Module3D`; `Core/` means `Assets/Scripts/HBP/Core/`; `Quest/` means `Assets/Scripts/HBP/Quest/`; `Transfer/` means `Assets/Scripts/HBP/Transfer/`. Bare `Base3DScene`, `Column3D`, manager and `Sphere` filenames refer to `Data/Module3D` and its subfolders.

**Table notation.** `S` = live scene; `C` = live column; `M` = live manager; `direct` = existing common runtime operation/property that can be used by a future applier; `gap` = no safe in-place state applier or complete capture yet. `D1`/`Q1` etc. identify **planned** Desktop-origin and Quest-origin driver checks, not passing tests. `O1` etc. are planned offline/conflict checks. `local` means deliberately absent from the shared schema. All shared rows require before/after canonical capture and scientific-output parity checks in addition to the named scenario. For a global toolbar action, record the resulting value **per affected column**, not the toolbar's `IsGlobal` toggle.

Column, site, cut, ROI and sphere `field 1` are membership/tombstone fields. Column, cut, ROI and sphere `field 2` represent order where applicable. This mapping is a contract definition; it does not claim S2 capture/apply or parity tests have passed.


The checklist maps directly to the matrix rows. It is a design input for S1, not a claim that `VisualizationConfiguration` already stores these values.

- [ ] **Identity and ordering:** schema version, epoch/visualization/manifest identity, accepted revision; stable column ID, site `FullID` scoped by column, session-stable cut/ROI/sphere IDs, collection order and tombstones. A cut's current `ID` is reassigned after removal (`Base3DScene.cs:1558-1562,1596-1600`).
- [ ] **Scene resources and topology:** selected mesh or runtime preview MRI identity, representation, mesh part, selected MRI and implantation, paired dependency versions/hashes, full and simplified surface mask keyed to exact topology. A resource transition and its dependent mask form one atomic group.
- [ ] **Scene rendering inputs:** brain/cut colors, colormap, edges, transparency and alpha, strong cuts, automatic-cut policy, hide-blacklisted, show-all and site gain; MRI calibration; explicit activity projection intent if manual compute/remove can differ with identical other inputs.
- [ ] **Cuts:** stable ID/order, orientation, normal, flip, position. Treat these four geometry values as one atomic group. Decide how automatically regenerated cuts retain or replace IDs.
- [ ] **ROI:** stable ROI/sphere IDs and order, name, each sphere's scientific position and **influence** radius, active ROI ID. Exclude animated display radius, edit-handle selection and creation mode.
- [ ] **Per-column common state:** column modality, activity alpha, selected scientific site, resource identity, navigation timeline index/play/loop/step and clock anchor when playing. Record actual final values for each column affected by global controls.
- [ ] **Per-site state:** filtered inclusion, blacklist, highlight, color, ordered labels and moved scientific position. Scope identity to column plus full site ID, especially where several columns reuse a site.
- [ ] **Modality state:** anatomy distance; static label and span/distance; iEEG and CCEP span/distance; CCEP source mode/site/MarsAtlas label; fMRI and MEG selected resource, four thresholds and three hide flags. Preserve resource order mapping or replace saved indices with validated identities.
- [ ] **Atlas/fMRI/localizer state:** Mars/JuBrain display and alpha; IBC and DiFuMo display/source; localizer display/protocol/data/bloc/time/span; atlas fMRI alpha and four thresholds. Pin or transfer every referenced resource before accepting dependent state.
- [ ] **Correlations:** comparison target, display intent and either reproducible inputs with parity proof or a content-addressed prepared result. Compute/load/reset are not safely represented by current configuration.
- [ ] **Local exclusions:** Desktop camera, views and layout; Quest wrapper pose/scale, recentering and tracked devices; hover, selection handles, tool modes, progress and file paths. Verify non-propagation.

## Capture and dependency findings that gate S1–S3

1. `Base3DScene.CaptureConfiguration` (`Data/Module3D/Base3DScene.Configuration.cs:188`) does read many live scene and manager values, but it omits selected column/site, active ROI, site filtering and moved positions, timelines, correlations and manual activity intent. `Column3D.CaptureConfiguration` (`Data/Module3D/Column3D.cs:671`) captures site flags/color/labels, not `IsFiltered` or transforms. Saved `Visualization.Configuration` is therefore not a live sync snapshot.
2. `DesktopSceneCapture.CaptureForQuestAsync` (`Transfer/Scene/DesktopSceneCapture.cs:19,144-214`) sends a prepared whole scene and functional resources. `ScenePayload` (`Transfer/Scene/ScenePayload.cs:6-58`) carries resource lists and a session/revision, not a live operation stream. `QuestAnatomySession.PublishAsync` (`Quest/Runtime/QuestAnatomySession.cs:321`) deduplicates deliveries by transfer ID; it does not apply incremental revision ordering. Resource manifest IDs and hashes need an explicit session lifetime.
3. `Base3DScene.Update` (`Data/Module3D/Base3DScene.cs:831-855`) computes geometry, cuts, textures, functional surfaces and sites from invalidation flags. `BasicTimeline.Play` (`Core/Data/Loaded/Processed/Timeline.cs:105-124`) advances automatically and may stop/reset at the end. These automatic transitions are state changes to capture, while texture/mesh recomputation is derived output. Quest application must reject obsolete computation before it becomes visible.
4. `ROIManager.UpdateROIMasks` (`Data/Module3D/Modules/ROIManager.cs:169-198`) makes active ROI selection scientific. `Sphere.Update` (`Data/Module3D/Objects/Sphere.cs:125`) animates `Radius`, whereas `InfluenceRadius` (`Sphere.cs:91,178`) is the mask input. Sampling the animated radius would create false edits.
5. Changing mesh, representation, MRI or implantation can invalidate cuts, site identities, masks and functional projections (`MeshManager.cs:210-352`; `Base3DScene.cs:1138-1155`). Pairing definitions can become stale when source protocols or tags change (`05-code-integration.md`, gap 9). A state revision must not reference unavailable or mismatched prepared resources.
6. No test in S0 proves Quest parity or full control coverage. The D/Q/O cells above are acceptance work for S2–S6. S1 must either define each **gap** precisely or change the product requirement explicitly; an unknown row blocks release.
