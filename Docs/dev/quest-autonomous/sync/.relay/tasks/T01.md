## Chosen binary contract
All integers and IEEE-754 binary32 values use little-endian encoding. Reject nonfinite floats and negative zero. Preserve requested color as four finite RGBA floats without clamping. Strings use strict UTF-8 with a `u16` byte length, NFC normalization, no control characters, nonempty content, and at most 256 bytes. Session, scene, incarnation, operation and reliable-stream IDs are distinct nonzero 16-byte identities. Resource/topology and column/site/cut IDs are distinct bounded text identities, never collection indices. A site is identified by `(columnId, fullSiteId)`.

The v2 mutation frame has a 136-byte fixed header followed by exactly `payloadLength` bytes. Offsets: 0 magic ASCII `HBS2` (4); 4 protocolVersion `u16` (=2); 6 messageKind `u16` (=1, mutation); 8 flags `u16`; 10 headerLength `u16` (=136); 12 payloadLength `u32`; 16 sessionId (16); 32 sceneId (16); 48 incarnationId (16); 64 messageId/operationId (16); 80 reliableStreamId (16); 96 reliableFrameSequence `u64`; 104 originSequence `u64`; 112 canonicalSequence `u64`; 120 observedCanonicalSequence `u64`; 128 originDevice `u8` (1 Desktop, 2 Quest); 129–135 zero reserved bytes. Flags bit 0 declares canonicalSequence present and bit 1 declares observedCanonicalSequence present; other bits reject. An absent sequence has value zero. A committed mutation requires nonzero IDs, reliable stream/frame sequence and origin sequence. A Desktop canonical mutation carries canonicalSequence; a Quest proposal carries observedCanonicalSequence, whose valid initial value is zero. Retry and canonical echo retain operationId. Precommit DTOs do not allocate wire sequences.

Validate magic, version, kind, header length, flags, reserved bytes and mutation payload length (at most 1024) before body allocation. Require exact frame length and checked arithmetic. Unknown required versions/kinds reject negotiation. Version 2 has no skippable header extension; later versions may explicitly define bounded optional extensions. T05 adds other message kinds with their own bounds without changing this mutation layout. TLS supplies transport integrity; no per-frame cryptographic hash is added.

Mutation payload: `schemaVersion:u16` (=1), `operationType:u16`, then the exact type-specific body. Type 1 `SetSiteColor`: bounded columnId, bounded fullSiteId, requested RGBA as four `f32`. Type 2 `SetCutDefinition`: bounded cutId, orientation `u8` (Axial/Coronal/Sagittal/Custom = 0–3), flip `u8` (0/1), numberOfCuts `u32` (1–65535), position `f32` in [0,1], and normal X/Y/Z as three finite `f32` forming a nonzero vector. This is the complete definition; runtime cut index is excluded. Type 3 `SetTimelineAnchor`: bounded columnId, index `i32` (nonnegative), playing `u8` (0/1), looping `u8` (0/1), step `i32` (1–1,000,000), monotonicAnchorTicks `i64` (nonnegative), and tickFrequency `u64` (positive, at most 10^12). The scene handler checks index against the prepared timeline length later. Wall-clock time is not conflict authority. Reject unsupported schema/type, trailing bytes, malformed UTF-8, invalid enums/booleans/IDs, nonfinite values and bounds violations.

Each validated operation derives an immutable descriptor; callers cannot supply arbitrary scheduling keys. The coalescing and single touched key is respectively `(scene, incarnation, SiteColor, columnId, fullSiteId)`, `(scene, incarnation, CutDefinition, cutId)`, or `(scene, incarnation, TimelineAnchor, columnId)`. Each supports latest-unsent coalescing and has no structural barrier. A later structural/control barrier seals earlier slots; T03 implements that scheduler. Three family-owned typed checkpoint records reuse their validated bodies with a `recordType:u16`, `schemaVersion:u16`, `bodyLength:u16` prefix. They support later checkpoint composition without a generic field map. Aggregate identity and reconciliation belong to later tasks.
