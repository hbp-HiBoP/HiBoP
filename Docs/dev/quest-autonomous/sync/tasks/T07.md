# T07 - Activity/invalidation concurrency foundation

## Objective
Remove global scene-update freezing and coarse activity invalidation before handler expansion.

## Shared context and dependencies
T04 mutation boundary; integration, job and matrix contracts.

## Scope and preserved contracts
Separate projection requested/policy/state/generation; version input leases; reject stale generation publish; deterministic projection-start/sensitive-operation ordering. Keep two-peer coordination for T14.

## Out of scope
T14 two-peer job/UI coordination and native-repository changes without refined scope.

## Automated acceptance criteria
A1. Data/Core/Sync Scene and focused tests compile. A2. Fake/controlled generator permits safe scene work while computing; manual stale state does not auto-restart. A3. Old generations cannot publish and both sensitive race orders are deterministic.

## Verification contract
Static gate then focused `Sync.SceneFocused` MCP EditMode tests, job polling and console inspection. If native integration is truly required, refine scope and apply hbp_core's native-first rule before starting.

## Human acceptance
Review scientific input lease and safety classification.

## Unresolved decisions
RESOLVED: `Base3DScene` owns the projection/input generations and captured column lease. Each leased column's `GeneratorWork` keeps its borrowed native handles and arrays alive until worker completion; no `hbp_core` change is needed. Scientific invalidation is limited to filtered/blacklisted mask changes; highlight, color, and label changes are presentation-only.

## Completion report
The scene now tracks projection request, automatic recompute policy, projection state, input generation, and projection generation separately. Projection starts only after prepared geometry is stable and no sensitive-operation scope is active. The boundary exposes a scoped sensitive-operation admission hook: mutation-first blocks start until scope disposal, while projection-first rejects the later operation. Manual stale state does not restart unless a manual request is pending. Each worker checks its lease before computation and per-column publish, so invalidated or superseded work cannot publish. A controlled scene test also confirms site rendering and typed state admission continue while a projection is computing; whole-scene legacy snapshots and geometry/resource replacement remain guarded. After configuration, geometry, and surface preparation, startup now restores the initial automatic projection request and marks the generator input stale for `ShouldStartActivityProjection`. Its one-time initialization guard preserves explicit removal. Public `UpdateGenerator()` now creates an explicit request, while frame updates use a separate start path behind the automatic-policy gate. `PrepareRenderingAsync` waits while an explicit request is pending or computing, even when an earlier generation remains marked ready; stale state without a pending request can still settle idle. Legacy synchronized cuts and geometry invalidate pending collider publication at acceptance; timeline and presentation-only changes do not. Regression tests cover automatic startup/removal, manual stale gating, direct explicit updates, the Quest view recalculation path, Ready-to-request rendering preparation, and stale collider rejection after a synchronized cut move.
