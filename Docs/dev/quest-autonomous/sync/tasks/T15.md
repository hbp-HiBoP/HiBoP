# T15 - Product Quest controls

## Objective
Connect approved Quest interactions to already-tested shared operations, keeping presentation-only gestures local.

## Shared context and dependencies
T09–T14 drivers/handlers; matrix and prefab-first project rules.

## Scope and preserved contracts
Use existing operations/jobs with local optimistic application. Author controls in the appropriate Quest prefab with serialized references; preserve protocol and domain logic.

## Out of scope
New operation types, alternate domain logic and runtime-created authored UI.

## Automated acceptance criteria
A1. Quest runtime and focused test assemblies compile. A2. Every exposed control reaches its previously tested handler and passes its driver behavior. A3. Local-only gestures do not emit shared mutations; prefab references and invalid-input behavior are verified.

## Verification contract
Static gate, focused Quest PlayMode/EditMode MCP filters after the product control list is fixed; poll jobs and inspect console. Visual control acceptance remains manual.

## Human acceptance
Approve the specific product UI scope and inspect Quest controls in headset.

## Unresolved decisions
The first product slice is approved in [Interfaces et interactions Quest HiBoP](../../quest-controls-ux-plan.md), with ordered, individually verifiable implementation lots. It covers the independent Quest theme, reusable spatial windows and connection window, persistent horizontal toolbar, universal targeting with trigger arbitration, immediate contact-based site selection, and cut controls with proximity handles. A joystick wheel and persistent selected-cut workflow are excluded from this slice.

Follow that plan's control-to-operation mapping and handler qualification prerequisites before exposing scientific controls. Automatic last-interacted-brain scene/column synchronization remains explicitly in T17. Multi-scene support and new operation types are not introduced here.

UNRESOLVED: exact prefab/asset paths and final component names are fixed per lot; headset tuning, focused test names/counts and the remaining handler evidence are implementation and verification work, not pending approval of the product interaction model. This approved slice does not claim coverage of every T09–T14 operation.

## Completion report
Map each control to its existing operation, test and visual result.

2026-10-07: lots 01–05 of the approved UX plan are implemented. The independent Quest theme, two-hand pointer, reusable managed windows, delayed following/pinning and toolbar are wired in the authored Quest prefabs. Display reuses the existing local visibility/recenter paths and explicit projection job entry point. Focused verification passed 18 EditMode and 18 PlayMode tests, the assembly dependency gate, and console inspection. See the plan's delivery appendix for the control mapping, test filters, initial settings and manual checklist. Headset acceptance is pending; site selection and cut controls are not yet delivered, so this does not complete T15.
