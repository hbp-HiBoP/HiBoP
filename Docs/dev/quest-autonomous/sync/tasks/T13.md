# T13 - Online correlation job

## Objective
Run Desktop-only online correlation compute/load and transfer one typed canonical result.

## Shared context and dependencies
T12 job lifecycle; long-job, wire and matrix contracts.

## Scope and preserved contracts
Serialize bounded command/data/provenance, never a Desktop file path; chunk/interleave; offline capability gate; atomic apply, cancellation and failure.

## Out of scope
Quest online compute and partial pair publication.

## Automated acceptance criteria
A1. Affected assemblies compile. A2. Compute and load share one result contract and typed checkpoint. A3. Partial pairs never publish; control/interactive traffic progresses during large result transfer; cancellation, failure and stale generation are tested.

## Verification contract
Static gate, focused SceneFocused and needed bulk/Loopback MCP tests; poll job, inspect console and record counts/timing.

## Human acceptance
Review result provenance and large-data responsiveness.

## Resolved decisions
Correlation result data and provenance live together in `HBP.Data.Module3D`: `Column3DIEEG` owns the applied correlation and mean matrices plus their `CorrelationProvenance`, while detached `CorrelationResultData` carries both matrices and provenance during compute/load. The canonical `CorrelationResultResource` serializes the complete prepared IEEG column/site roster and all matrix pairs with per-column source metadata; it contains no Desktop path.

## Completion report
### Data and provenance contract

`CorrelationProvenance` records source (`Computed`, `Imported`, or `Unknown`), patient/column, dataset, protocol, bloc, data-info identities and names, normalization, threshold, and Bonferroni setting. The canonical HCR2 resource validates the full prepared column/site roster and finite matrix values before it can be applied. A `SetCorrelationResult` binds those bytes to one operation and generation and is an all-scene barrier. The 8 MiB resource bound is also enforced on the mutation/checkpoint data.

The outer typed scene checkpoint schema remains version 6, and the T13 record uses inner schema 2. It stores canonical correlation bytes or an explicit empty marker plus an independently encoded `DisplayCorrelations` flag. Applying a populated record restores matrices and provenance, then restores the captured display setting. Applying the empty marker clears matrices and provenance, then restores that same setting. The live compute/load result path remains unchanged and still enables correlation display after a successful result.

Compatibility is preserved at both levels. Inner T13 schema 1 is decoded using its former behavior: populated results imply visible and the empty marker implies hidden. Outer checkpoint schemas 1–5 have no T13 record; applying them leaves the current correlation data and display setting untouched. The typed checkpoint round-trip test checks visible and hidden populated results, visible and hidden empty markers, matrix values, provenance, schema compatibility, and byte-stable re-encoding.

### Atomic publication and exclusion evidence

Correlation resources are completely decoded and validated against the prepared roster first. `Base3DScene.ApplyCorrelationResults` validates every column and matrix and builds detached matrix copies before replacing any live column data in one synchronous main-thread call. `T13CorrelationApply_RejectsInvalidLaterColumnBeforePublishingEarlierMatrices` supplies an invalid second-column matrix and confirms the preexisting matrix values in both columns remain unchanged. The socket transfer test confirms complete resource application, provenance preservation, exact `Ready` for job/generation 23, and interleaved traffic before reporting completion.

Filter and correlation starts now reject one another symmetrically on Desktop and Quest, including Quest local offline flags. Regression cases cover both job orderings and assert that the rejected second start leaves the first job uncancelled and its sensitive-activity scope held. The offline flag test checks each flag ordering.
