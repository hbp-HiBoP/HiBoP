# T17 - Multi-scene lifecycle, selection and global reconciliation choice

## Objective
Multiplex scenes and apply one user reconciliation choice to common incarnations without redesigning the protocol.

## Shared context and dependencies
T16 reconciliation; lifecycle and wire contracts.

## Scope and preserved contracts
Multiple scene/incarnation routing, full-delivery registration, online close with watermarks, per-scene jobs/presentation, last Quest-brain scene/column selection and per-scene choice outcomes.

## Out of scope
Cross-scene rollback promise and reattaching missing/orphan scenes.

## Automated acceptance criteria
A1. Affected assemblies compile. A2. No cross-scene operation; slow/closing scene does not block another; selection routes to matching Desktop scene/column. A3. One choice yields individual per-scene success/failure and excludes missing/orphans.

## Verification contract
Static gate then focused SceneFocused and, for authored UI, PlayMode MCP filters; poll jobs and inspect console. Require scene-specific names/counts and fresh run timing.

## Human acceptance
Inspect per-scene status and selection behavior.

## Unresolved decisions
UNRESOLVED: exact UI/prefab ownership, future tests/counts.

## Completion report
Report per-scene closure, failures and manual UX.

## Preference changes requiring scene reload

Desktop remains authoritative for preferences. Implement the complete per-scene cycle after this session-preferences milestone:

1. Identify all incarnations affected by a preference change.
2. Close Desktop and Quest incarnations with operation barriers, cancellation and awaited native cleanup.
3. Apply preferences and reload affected Desktop scenes.
4. Deliver each scene fully into a new incarnation.
5. Present per-scene success/failure and retry options.

Until this cycle exists, reject reload-requiring normalization changes while a shared incarnation is open, before mutating global settings, saving or transmitting. Preserve the existing Desktop reload for exclusively local scenes.
