# T05 - Persistent duplex transport v2

## Objective
Carry v2 records bidirectionally over one persistent authenticated connection without Unity scene dependencies.

## Shared context and dependencies
T01 envelopes, T03 scheduler, wire/transport contracts.

## Scope and preserved contracts
Independent read/write loops, NoDelay, event-driven writer, bounded framing, multiplexing, one liveness owner and clean cancellation. Preserve pairing authentication.

## Out of scope
Real-scene apply and UI controls.

## Automated acceptance criteria
A1. Transport and Sync assemblies/tests compile. A2. Loopback fake peers prove both directions, fragmentation/combination, resume/replay, origin gaps and lane fairness. A3. Malformed lengths, lost ephemeral ACK/ping, large unacknowledged bulk with bounded cancel/interactive progress, partial cancellation and blocked/empty/full shutdown pass without arbitrary sleeps.

## Verification contract
Static gate, focused `Sync.Fast` contract tests then `Sync.Loopback` EditMode MCP tests; poll each job and inspect console, exact counts and times.

## Human acceptance
Reviewed the single liveness owner and transport-failure boundaries in the completion report.

## Unresolved decisions
None.

## Completion report
- Added a fixed 136-byte v2 transport header with a 65,536-byte payload cap (65,672 bytes maximum frame). Resume state is bounded to 128 streams; scoped rejection diagnostics are capped at 512 UTF-8 bytes. The receive side checks the fixed header and declared payload length before allocating a body buffer.
- Typed application mutations use the unchanged T01 `HBS2` envelope, with bytes 129–135 zero. `V2PersistentTransport.EnqueueMutation` requires both sequence metadata arguments and validates them by origin: Desktop needs its authoritative nonzero acceptance-order canonical sequence and no observed sequence; Quest needs its latest observed canonical sequence (zero is valid before the first canonical operation) and no canonical sequence. The scheduler and immutable reliable frames preserve these values through replay. Other T05 transport records retain their `HBT2` lane/chunk/schema framing.
- Transport-owned bounds are 64 direct ephemeral controls, 128 out-of-order records, 256 incoming records / 4 MiB, and 128 reliable streams per resume table. Each direction permits 126 unretired bulk ordinals alongside its two permanent streams. The scheduler's reconnect grace is 500 ms. `V2PersistentTransport` owns the only liveness loop; ACK and ping/pong records are ephemeral, and reconnect clears stale ephemeral controls before queuing `ResumeHello`.
- Bulk stream IDs carry a per-session, per-origin ordinal. The scheduler advances a contiguous retirement watermark only after a bulk stream is fully acknowledged or cancelled; it bounds out-of-order retirements to the 126-ordinal window. Resume and live `BulkStreamRetirement` records propagate that watermark. The receiver accepts monotonic retirement advances across ordinals with no observed stream (including allocations cancelled before transmission), while retaining the backward-watermark and pending-gap checks. It keeps exact per-stream replay watermarks until peer confirmation, then retires them; late duplicate bulk data is suppressed and late ACKs for retired IDs are ignored. Active inbound state remains bounded.
- Protocol/framing/session/ACK/origin-sequence violations, other permanent loop failures, and scheduler required-work overflow fault the transport session, close the active stream, complete the incoming queue, and wake pending readers. Failure to retain a required wrong-scene rejection also faults the session. Stream I/O failure and bounded receive backpressure close the connection and enter reconnect grace; caller cancellation and disposal close the stream and stop both loops. A wrong-scene operation queues a reliable operation-scoped rejection and is not delivered to the application. Reliable receive watermarks advance only after bounded queue admission, allowing a backpressured record to replay safely. Disposal wakes every pending incoming reader.
- Production entry is `QuestPairing.OpenV2ReplicaAsync`, which uses the existing command-14 pinned TLS and credential authorization path before handing the stream to `V2PersistentTransport.RunConnectionAsync`. The existing Quest `ServeAsync` command-14 `receiveReplica` callback remains the server-side entry; its per-peer boundary handles expected v2 protocol exceptions so malformed peers do not fault listener shutdown. TCP clients and accepted peers enable `NoDelay`.
- Human review: the one liveness owner is `V2PersistentTransport.LivenessLoopAsync`; protocol failures fault, connection I/O/backpressure enters grace, and explicit cancellation/disposal shuts down the owned stream and loops.
- T01/T05 cross-codec coverage tests Desktop and initial Quest mutations in both directions. Production loopback sends verify a Desktop canonical sequence of 11 while its origin sequence is 1, a Quest observed sequence of 23, and a replayed Desktop canonical sequence of 41.
