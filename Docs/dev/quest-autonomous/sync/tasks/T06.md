# T06 - Online sequencing, transient reconnect and early Quest proposal driver

## Objective
Prove bidirectional canonical authority and failure handling for the three vertical-slice profiles.

## Shared context and dependencies
T03–T05 outputs; replication, lifecycle and wire contracts.

## Scope and preserved contracts
One fake/prepared incarnation, Desktop acceptance/per-key indexes, Quest optimistic proposals and authoritative correction, fake-clock 500 ms grace and bounded retry.

## Out of scope
Broad matrix coverage, real-scene cutover and offline merge.

## Automated acceptance criteria
A1. Scene/Quest assemblies and tests compile. A2. Both directions converge for color, cut and timeline. A3. Lost ACK does not double-apply; within-grace reconnect is silent; expiry preserves view and abandons history; stale/same-key/disjoint-key cases match the plan.

## Verification contract
Static gate then focused `Sync.SceneFocused` MCP EditMode driver tests, with completed job, console and timing evidence; zero/skipped/stale runs fail.

## Human acceptance
Review correction UX and view preservation.

## Unresolved decisions
Resolved before implementation: scene-scoped acceptance-order authority and Quest optimistic handling live in `HBP.Sync.Scene` beside `V2SceneMutationBoundary`; the acceptance fixture and driver cases live in `HBP.Transfer.Scene.Tests`. The production Desktop authority delegates per-key admission to `V2OperationLedger`; Quest retries reuse `V2OutgoingScheduler`'s reliable replay frames and fake-clock grace.

## Completion report
- **Desktop to Quest:** `V2SceneMutationBoundary.MutationProposed` feeds `V2DesktopMutationAuthority`, which assigns acceptance-order canonical sequences and publishes `CanonicalReady`; `V2QuestMutationDriver.ReceiveCanonical` applies the typed color, cut, or timeline setter once. `DesktopCanonicalMutations_ConvergeForColorCutAndTimeline` covers three canonical edits.
- **Quest to Desktop:** `V2QuestMutationDriver.ApplyOptimistic` applies through the prepared boundary and queues a reliable Quest proposal with its observed canonical sequence. `V2DesktopMutationAuthority.AcceptQuestProposal` admits it through the ledger, applies it on Desktop, then echoes the canonical value. `QuestOptimisticProposals_ConvergeAndMatchingEchoesDoNotApplyTwice` covers all three mutation families and confirms matching echoes do not call the setters twice.
- **Lost ACK and idempotency:** `LostCanonicalAcknowledgement_RetryReusesFrameAndDoesNotDoubleApply` verifies identical reliable-frame replay and cached duplicate canonical output.
- **Stale and correction ordering:** `StaleSameKeyProposalGetsDesktopCorrectionWhileDisjointProposalIsAccepted` verifies a current same-key correction while a stale proposal on another key is admitted. `MatchingCorrectionWatermark_PreventsOlderCanonicalFromRollingBackOptimisticValue` covers an equal optimistic/correction value followed by an older same-key canonical.
- **Reconnect grace:** `GraceReconnectIsSilentAndExpiryAbandonsHistoryWithoutChangingTheView` reconnects at 499 ms with the same frame and no offline notice, then expires at 500 ms, abandons the pending operation, and retains the optimistic scene value.
- **Prepared-target validation:** `InvalidTimelineProposal_IsRejectedBeforeLedgerAdmission` sends index 100 from a 101-frame Quest timeline to a 100-frame Desktop timeline. Desktop returns a targeted correction without advancing its canonical sequence; a following valid index 99 proposal is accepted as sequence 1.
- **Scheduler pressure and recovery:** `QuestSchedulerPressure_DefersProposalUntilCapacityReturns` fills the one-record scene queue, verifies the optimistic edit remains pending in the bounded deferred queue, then frees capacity and confirms the same proposal is transmitted and converges.
- **Desktop history exhaustion:** `DesktopLedgerOverflow_FaultsAuthorityAndRequestsSessionDisconnect` limits the ledger to one operation, then verifies a second already-applied local edit faults the authority, requests session disconnection, leaves the canonical sequence unchanged, and blocks further Quest proposals.
- **Human acceptance review:** rejection correction reads and applies only the authoritative value for the rejected key through the existing typed scene boundary. Grace expiry clears retry/proposal history and transitions the driver to `OfflineLocal` without restoring stale values over the current Quest view.
