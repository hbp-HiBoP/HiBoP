# T16 - Single-scene checkpoint reconciliation UX

## Objective
Reconcile one common incarnation from its last confirmed common state: combine independent Desktop/Quest changes and resolve only conflicting groups by user choice.

## Shared context and dependencies
T06 authority plus completed handler/checkpoint families; replication and lifecycle contracts.

## Scope and preserved contracts
Checkpoint identity, silent equal reconnect, in-memory common base, semantic three-way merge, Desktop/Quest choice per dependent conflict group, delayed progress using the existing loading UI, bounded cancelable staging, interaction lock, prevalidation, commit/failure, orphan indicator and retry. Scene/column pose remains local. Atlas files must already be present in both builds and are never transferred at runtime. Session preferences remain Desktop-authoritative.

## Out of scope
Persistent offline history and T17 multi-scene UI. Exhaustive scientific/hardware qualification, precise performance instrumentation and numerical performance gates are deferred by the user's decision on 8 October 2026. Previously accepted Quest UX remains closed.

## Automated acceptance criteria
A1. Affected assemblies compile. A2. Independent changes combine; identical changes are silent; conflicting or dependent changes are resolved together and converge without source resources; offline Desktop close leaves Quest local. A3. Interrupted staging applies nothing, commit failure is explicit/out-of-sync, retry works and no reconciliation history survives process death by contract. A4. Shared state, including hemisphere site placement, survives initial delivery and checkpoint restoration while local pose is preserved.

## Verification contract

### Headset acceptance checklist

Keep both applications open during these tests. Use the current Desktop code (Unity Play is sufficient). For a real disconnection, unplug USB and turn off Quest Wi-Fi, then wait until the application reports local/disconnected use. Restore Wi-Fi for reconnection without publishing another copy of the scene.

1. Before initial publication, move all sites left or right on Desktop. The Quest should receive that placement. Moving or rotating the brain locally must remain local.
2. Disconnect and reconnect without changes: synchronization should resume without a conflict choice.
3. While disconnected, change a site's color on Desktop and move a manual cut on Quest (disable automatic cuts for this example). After reconnection, both changes should remain, with the Quest brain pose unchanged. Subsequent live edits should propagate in both directions.
4. While disconnected, move the same manual cut differently on both sides. Reconnection should offer a readable choice; try keeping Desktop, then repeat keeping Quest. Only conflicting changes should follow the choice; independent changes should remain.
5. If a transfer interruption is encountered, the status should clearly indicate incomplete synchronization and allow retry. Desktop session preferences should prevail regardless of the scene choice. The original cancellation test was validated before the user requested that the conflict dialog require a choice; that dialog now offers only Desktop and Quest.
6. Disconnect, close the shared visualization on Desktop without quitting the application, then reconnect. The Quest copy should remain usable locally, with a clear status that it is no longer shared.

During these scenarios, assess readable messages, interaction blocking during reconciliation, useful loading feedback and perceived responsiveness. Record unexpected behavior rather than applying a numerical performance threshold.

Desktop now requires a confirmed peer resume handshake before ending the bounded reconnect attempt. Rejected or silent peers let the live owner expire, retaining the common scene state for full reconciliation. Expected cancellation of that owner's incoming reader is handled without reporting a spurious receive error. These changes affect Desktop reconnect behavior; the installed Quest APK did not need replacement for that correction. The user subsequently validated the corrected reconnection on the headset.

The two new rejected/silent-resume regressions failed before the correction. ## Preferences after disconnection

The preferences authority is always Desktop, independently of the chosen scene reconciliation direction. The session-preferences milestone abandons disconnected operations without replay. T16 must define an explicit fresh preferences reconciliation after reconnect, apply reload guards, and never import Quest preferences as the scene choice. Do not silently replay old preference snapshots or manual atlas operations.
