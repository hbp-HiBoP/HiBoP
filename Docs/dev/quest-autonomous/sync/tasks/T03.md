# T03 - Pure scheduler, backpressure and job freshness

## Objective
Prove bounded lane scheduling, independent reliable streams, coalescing and job freshness before networking.

## Shared context and dependencies
T01 types; wire, transport and verification contracts.

## Scope and preserved contracts
Keep structural records in scene-operation order, assign origin sequence at wire commitment, retain written reliable previews unchanged, route oversized bodies via descriptor plus independent bulk stream, and bound every queue/cache.

## Out of scope
Socket loops, Unity scene binding and broad operation families.

## Automated acceptance criteria
A1. Sync runtime/tests compile. A2. Deterministic fake-time tests cover lanes, per-stream sequences, coalescing/barriers, bulk fairness, conflict indexes, checkpoint identity and stale jobs. A3. Test overflow, ACK loss, retry, preview pressure, large atomic routing and cancel/interactive progress during bulk resume within measured bounds.

## Verification contract
Static gate, then focused `Sync.Fast` MCP EditMode run in `HBP.Sync.Tests`; poll completion, inspect console, require named fresh tests and execution time.

## Human acceptance
Review measured inline threshold, fairness burst and queue limits.

## Resolved decisions
- Inline threshold: 4 KiB. Bodies at or below 4096 bytes stay inline; 4097 bytes and above route through a scene-stream descriptor and an independent bulk stream.
- Initial bulk chunk size: 16 KiB. Initial interactive burst: 8 scene records before a pending bulk chunk is selected.
- Initial bounded capacities: scene pending 256 records / 256 KiB with 16 records / 16 KiB reserved for scene control; session control pending 64 records / 64 KiB with 8 records / 8 KiB reserved; reliable retransmit log 128 frames / 256 KiB with 8 frames / 16 KiB reserved; 8 bulk transfers, 16 MiB per body, 32 MiB total; 128 touched keys per record; operation ledger 4096 operation IDs / 65536 keys / 4096 scene-incarnation watermarks. These are pure scheduler starting limits pending production transport profiling.
- A short in-Unity managed timing sample showed a cost discontinuity across inline routing. It is a scheduler tuning measurement, not a network or end-to-end latency claim.

## Scope limitation
This is a pure pre-network, single-owner scheduler/state model. It does not add socket loops, Unity scene application, concurrent producer synchronization, or physical transport measurements. A transport owner must serialize access before connecting Unity producers and writer loops. Producers must supply encoded bodies and descriptors derived from validated family operations; only T01's site-color, cut-definition and timeline-anchor typed families currently feed mutation/checkpoint helpers. Treat the limits as tested starting points until transport profiling is available.
