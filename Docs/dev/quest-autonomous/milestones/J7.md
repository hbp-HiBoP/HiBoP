## Validation manuelle du jalon

Choisir tester/différer ; si tester, refaire le parcours complet sur la distribution identifiée.

L'agent fournit les binaires, fixture, commandes/boutons exacts et résultats
attendus via les rapports des tâches. Le propriétaire valide les aspects
visibles et les décisions scientifiques demandées ; il n'est pas chargé de
remplacer les tests automatisables.

## Review attendue

Lire d'abord le résultat de démonstration, puis les 3–5 points prioritaires de
chaque rapport : flux de données, règle partagée, frontière plateforme et
preuves. Les détails de code sont liés à des symboles/lignes effectifs, et les
prefabs à leurs objets/champs. Aucun succès ancien ne remplace un test du produit.

## Mesures et artefacts

Décision et cible, puis mêmes familles de mesures que Mac.
Rapports reports/QUEST-NNN.md, manifestes evidence/QUEST-NNN/manifest.json et
[registre](../TASK-STATUS.md). Les gros artefacts peuvent rester ignorés avec
chemin/hash consignés ; cela doit être indiqué au lecteur.

## Fin et condition de révision

Le jalon est qualifié lorsque ses tâches requises sont implémentées, leurs preuves
techniques pertinentes réussies et les validations manuelles requises obtenues.
Une preuve manquante doit rester visible. Le choix explicite de différer Linux clôt le jalon par report et rend QUEST-028/029 non applicables.

Une décision de report termine le jalon sans prétendre que Linux est supporté.

Le jalon suivant n'est pas lancé automatiquement. Une demande explicite d'une
tâche suivante suit le [contrat d'exécution](../TASK-WORKFLOW.md), qui distingue
les dépendances vraiment bloquantes des retours UX encore en attente.
