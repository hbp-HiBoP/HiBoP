# Development tools

Tools consume versioned source/configuration, declared SDKs, or dependencies
pinned by version and hash. A clean checkout must not need an old local campaign
under `.artifacts`, an untracked fixture, or another developer's workstation paths.
Generated outputs and caches are disposable; a tool must create/acquire them or
accept the build/measurement to inspect as an explicit input.

Product regression tests belong in `Assets/Tests`. Keep external scripts for
build/toolchain operations, testing those scripts in their own language, and
device or cross-platform evidence that an Editor test cannot establish.

## Maintained entry points

| Tools | Purpose and inputs |
| --- | --- |
| `format-code.cmd`, `Format-Code.ps1` | Format changed C# using `.config/dotnet-tools.json`. Requires the solution generated by Unity for this checkout. |
| `check-assembly-dependencies.ps1`, `assembly-dependency-policy.json` | Validate versioned assembly definitions and dependency direction. `test-check-assembly-dependencies.ps1` generates its own isolated fixtures. |
| `run-sync-tests.cmd`, `run-sync-tests.ps1` | Select and run existing Unity test tiers. `-PlanOnly` works with an open Editor; execution requires the matching Unity version and a closed project. |
| `update-native-plugins.cmd`, `Update-NativePlugins.ps1` | Acquire pinned native packages using `NativePlugins.json`, validate and install transactionally with `NativePlugins.lock.json`. Local import packages are explicit inputs produced by the owning native repository's versioned build scripts. |
| `Test-NativePluginUpdater.ps1`, `Test-NativePluginAndroidUpdater.ps1` | Network-free tests of the PowerShell updater, including rollback, using generated test-owned packages. These protect tooling, not Unity runtime behavior. |
| `Test-QuestApk.ps1` | Inspect an explicit `-Apk` and write `-ReportPath`; validate packaging, native content and installed lock hashes. Used by CI and after local builds. |
| `Test-NoAdb.ps1` | Reject ADB binaries in an explicit distribution directory/archive. Used by packaging CI. |
| `Prepare-QuestMdns.py`, `QuestMdns/` | Rebuild the managed mDNS adaptation from hash-pinned upstream inputs and versioned local sources. Creates its own `.artifacts` cache; see `QuestMdns/README.md` for the SDK pin. |
| `Connect-QuestAdbWifi.ps1` | Discover/connect an authorized Quest using the installed Android SDK. Optional connection cache is created by this tool. |
| `Export-QuestSelectionLab.ps1` | Retrieve actual device trial records and export CSV; requires an explicit device serial and an executed Selection Lab session. |
| `Run-QuestNativeProbe.ps1` | Exercise native loading/callbacks/ownership in a development IL2CPP Quest player. Requires explicit `-Serial` and `-Apk` built from this project. Generates its own synthetic native fixture on device; never selects a historical APK implicitly. |
| `Run-QuestSceneQualification.ps1` | Collect common-scene numerical evidence on an already running development Quest player with a published six-modality scene; explicit `-Serial` and fresh `-Evidence` directory. Optional USB interruption measures real device behavior. |
| `Compare-SceneQualification.py`, `Test-SceneQualificationComparator.py` | Compare explicitly selected exports from `SceneQualification` across platforms, including scientific arrays and cut textures. Unit tests generate small synthetic reports. Numerical deltas are not a blanket scientific tolerance. |
| `Run-DisplaySyncBaseline.ps1`, `Summarize-DisplaySyncBaseline.py` | Measure actual Desktop/Quest display publication and summarize explicitly selected runs. The runner requires the executable, project, device serial and output directory; no historical dataset or build is assumed. |
| `analyze-sync-baseline.py`, `test_sync_baseline.py` | Analyze current schema-2 telemetry recordings supplied explicitly. Tests generate their own recordings and reject incomplete/ambiguous evidence. |
| `InflationReference/` | Generate/verify versioned geometric oracles and render comparisons. NumPy/NiBabel/Matplotlib and optional Workbench are scientific tooling; these scripts do not test HiBoP's runtime inflation algorithm. |

Device scripts use `adb` from `PATH`, or an explicit `-AdbPath` (`-Adb` for the
display runner). Running an on-device diagnostic does not establish visual/XR
acceptance. These scripts are not run by ordinary product regression tests.

## Builds and fixtures

Use Unity Build Profiles or `HBP.Dev.HBPBuilder.BuildFromCommandLine` for players;
the version comes from `codemeta.json`. Build native libraries in their owning
repositories, then use the updater. The old connection-campaign build wrapper
and standalone Android math bootstrap have been removed.

`SyntheticSceneProjectFixture` in `Assets/Tests/PlayMode/HBP.PlayModeTestUtilities`
generates iEEG and six-modality projects in each test's temporary directory from
versioned fixtures. `QuestAnatomyFixtureTests` and `SceneRestorationPlayModeTests`
use it directly; no Python preparation or pre-existing `.artifacts` input is
required. Anatomy/contact fixture coverage also lives in `QuestAnatomyFixtureTests`.

Historical prototype launchers, old trace readers, signing initialization and
their campaign-specific comparators are available through Git history. Paths
and hashes retained in `NativePlugins.lock.json` or `Validation/Quest` describe
the tools used for those historical results; they are not executable dependencies
of today's build. Keep that provenance intact when removing obsolete scripts.
